# 微前端 qiankun 系统学习系列(总纲)

> [← 返回主 README](../../README.md) · 微前端与 qiankun 全景:定位 / 核心机制地图 / 7 篇递进索引 / 学习心法

微前端要回答的问题其实很朴素:**当一个大应用已经长到"一个团队搬不动、一条发布线等不起、一套技术栈锁死"时,怎么还能像拆微服务一样把前端拆开?** 拆开后是 N 个**可以独立开发、独立部署的应用**,再由一个壳(主应用/基座)把它们**按需组装**回一个完整的用户体验。

qiankun(乾坤)是蚂蚁集团开源的微前端方案,也是国内落地最广、中文资料最全的一套(尽管现在更新放缓,详见[生态篇](./ecosystem.md))。它解决的是**"把一个完整 Web 应用,以页面级粒度装进另一个应用"**,可以浓缩成一句话:

> **qiankun = 应用加载器 + JS 沙箱 + 样式隔离。** 它不要求把业务拆成微服务,只要求子应用"愿意被加载、愿意交出生命周期"——这是它对比 iframe 与模块联邦的最大差异,也是它最值得深挖的地方。

## 学 qiankun 前先建立的心智

- **微前端不是"微服务"。** 它不解决后端那种进程级隔离,只解决**前端应用的组合与隔离**;而前端受制于"同一页面只有一个 `document`、一个 `window`",所以它的核心难点永远是两堵墙:**JS 全局环境隔离** 与 **DOM / 样式共享**。
- **qiankun 借壳 single-spa。** 它用 single-spa 的"生命周期驱动"做应用管理,自己补上 **HTML Entry**(直接加载一个完整网页的资源)与 **沙箱 / 样式隔离**——这两样才是 qiankun 的原创贡献。
- **隔离是相对的,不是绝对的。** 无论 Proxy 沙箱还是 Shadow DOM 样式隔离都有清晰的边界;**搞清"它能挡什么、挡不住什么"比背 API 更有价值**(这正是[沙箱篇](./sandbox.md)与[样式篇](./style-isolation.md)的着力点)。
- **一切先从"生命周期"理解。** 被拆出的子应用不再是"自己启动的页面",而是**一颗交给主应用调度的心脏**:`bootstrap → mount → unmount`。围绕这个模型,注册 / 路由 / 加载 / 卸载全部展开。

## 建议的动手路径

光看文档记不住,搭一个"1 主 + 2 子"的迷你示例最有效(本系列示例代码都可直接搬过去):

1. **主应用 + 两个子应用**(一个 Vue、一个 React 最能体会"多技术栈");两个子应用既要**独立可跑**,又能**被挂载**;
2. **单实例路由切换**:两子应用各挂在 `/a`、`/b`,切路由时打印 `bootstrap / mount / unmount` 日志,亲眼看到生命周期调度;
3. **做一次污染实验**:在子应用 A 里 `window.__x = 1`,切到 B 读 `window.__x` 体会沙箱;再把 `sandbox: false` 关掉对比一次;
4. **写样式污染实验**:A 里写一条全局 `.box` 样式,切回主应用页面观察是否残留;再开 `experimentalStyleIsolation` / `strictStyleIsolation` 对比;
5. **全局状态互通**:主应用登录后 `setGlobalState`,A / B 各自 `onGlobalStateChange` 消费;
6. 全部跑通后,去看[生态篇](./ecosystem.md)再想一遍:**"如果重新选型,我还用不用 qiankun?"**

## 学习心法

- **"它挡什么 / 挡不住什么"比"它有什么"更重要**:沙箱不挡 DOM 与事件、样式隔离解决不了 body 弹层、通信只建议传"轻量契约状态"——把三处边界读透,能避掉 80% 的线上坑。
- **子应用先学会"独立活",再学会"被接管"**:所有改造都围绕"同一份代码、两种运行环境(靠 `window.__POWERED_BY_QIANKUN__` 判断)"展开。
- **本系列默认 qiankun 2.x**(npm `qiankun`);3.0 长期停留在 rc,新工程是否入坑见[生态篇](./ecosystem.md)。API 细节以 qiankun.umijs.org 为准。
- **与既有知识强相关**:页面级集成(qiankun)与模块级共享(Module Federation)**可互补**,别二选一——对照 [Webpack Module Federation 学习笔记](../webpack/module-federation.md);子应用的打包本质就是 [Rollup / Vite 系列](../rollup/README.md) 讲的工程问题在"被他人加载"场景下的再讨论。
