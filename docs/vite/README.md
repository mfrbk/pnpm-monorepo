# Vite 系统学习系列(总纲)

> [← 返回主 README](../../README.md) · Vite 学习笔记:双引擎架构 / 工程化配置 / 插件系统 / 生态对比

会用 `npm create vite@latest` 起一个项目的人很多,但**只停留在"脚手架"层面的人,一旦面对"为什么启动这么快、为什么上线前还要 build、为什么报错要跑 tsc"这类问题就答不上来**。Vite 真正的价值不在"能起项目",而在它**刻意不同的架构选择**——用一个"开发/生产分裂"的双引擎,换来了 Dev 体验的代差。

本系列沿 **宏观 → 微观、原理 → 实战** 拆成四步,帮你建立完整的 Vite 知识体系:

```
① 核心概念与底层原理(双引擎)        ② 工程化配置与最佳实践(落地)
   原生 ESM + esbuild 预构建             vite.config / base / alias / proxy
   Rollup/Rolldown 生产打包               .env 与 import.meta.env / index.html 入口
   HMR 极速热更新
          │                                         │
          ▼                                         ▼
③ 插件系统与扩展能力(生态)            ④ 对比与生态视野(选型)
   Rollup 兼容插件 / 官方插件            vs Webpack 的取舍
   TS 集成(转译与类型检查分离)            框架 / 元框架 / Vitest 生态
```

## 为什么按这个顺序学

四篇之间同样是**层层递进**,先"懂为什么快",才能"配置得对"、"扩展得了"、"选得明白":

| 篇目         | 解决什么问题                                 | 学到后能干什么                                      | 依赖基础 |
| ------------ | -------------------------------------------- | --------------------------------------------------- | -------- |
| ① 双引擎原理 | "Vite 为什么这么快 / 为何 dev 与 build 两套" | 理解预构建、按需编译、HMR 边界,遇性能问题知道查哪里 | 无       |
| ② 工程化配置 | "真实项目里这些配置是干嘛的"                 | 独立写好 base/alias/proxy/env 与多页入口            | ①        |
| ③ 插件与 TS  | "想扩展 Vite 能力 / TS 为什么不当场报错"     | 看懂并手写插件、理清 esbuild 转译 + 类型检查分工    | ①②       |
| ④ 对比与生态 | "什么时候用它、什么时候回到 Webpack"         | 理性选型,并看清 Vite 工具链(Vitest/Storybook)版图   | ①②③      |

一句话:**① 让你"懂它为什么快",② 让你"会配",③ 让你"能扩",④ 让你"会选"**。对照阅读:[Webpack 学习系列](../webpack/README.md)——两者的核心概念(入口、代码分割、摇树、Source Map、缓存)高度同构,建议学完 Vite 后回头比对,工程化心智会成倍加固。

## 动手建议

结合一套最小演示项目效果最佳:

1. **观察"按需编译"**:冷启动 dev server 后,**不要在浏览器打开页面**,注意 CPU/编译无动静;第一次访问首页才逐个转译模块。体会"开发不做全量打包"与 Webpack 的本质差异。
2. **看一次预构建缓存**:打开 `node_modules/.vite/deps/`,能发现 node_modules 里的依赖被 esbuild 转成了带哈希名的 ESM 文件——这是"裸模块导入能跑通"的原因。
3. **开 `vite build` 对比**:看产物从"几百个模块文件"变成"几个 chunk",理解为什么上线仍需打包。
4. **写一个 10 行 inline 插件**:用 `transformIndexHtml` 或 `configureServer` 各写一次,再读 [插件篇](./plugins.md) 的钩子表。
5. **配三套 `.env`**:分别设置 `VITE_` 开头与普通变量,在代码里打印,验证**非 VITE\_ 前缀变量不可见**——一次就记住防泄露设计。

## 学习心法

- **Vite 最大的"知识点"是它的架构选择,不是它的 API**:所有"Vite 为何如此"的问题,几乎都能回到"开发=按需转译单个文件,生产=传统打包"这一个总开关上。
- **版本相关先看官方**:Vite 迭代快(本系列以 Vite 5/6 为基准),`Rolldown` 是正在进行的演进方向;文中涉及"未来方向"的表述以官方 roadmap 为准。
- **把它和 Webpack 系列对照着读**:同一件事(入口、别名、代理、TS)在两个构建器里的解法互为镜像,对照记忆远比孤立记忆牢固。

> 官方文档:vite.dev(指南 / 配置 / 插件 API 三栏)、vite.dev/guide/why 起步。相关体系:本仓库另有 [Webpack 学习系列](../webpack/README.md)。
